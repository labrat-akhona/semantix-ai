# AVX2 file vs qint8 file — the decision (2026-09-16)

Roadmap Now item 3. **Outcome: option (a) — the library should load a qint8 file on every CPU.**
The `model_quint8_avx2.onnx` variant is worse on *both* accuracy and latency on *both* CPU classes,
including the AVX2-only hardware it exists to serve.

## Method

`scripts/exp_avx2_vs_qint8.py` on the `exp/avx2-comparison` branch (deliberately not merged).
For each of `onnx/model_quint8_avx2.onnx` and `onnx/model_qint8_avx512_vnni.onnx`, forced via
`model_variant=`: the release gate on `data/popia_eval.jsonl` (SHA-256 verified against
`scripts/_popia_eval_hash.txt`, 150 pairs, explicit 0.5 threshold), then p50 latency over 50
`POPIAJudge.evaluate` calls on one fixed premise/hypothesis after 5 warmup calls.

GitHub hosted runners, onnxruntime 1.30.0, Python 3.11.16, single-threaded ONNX. Six shards per
push; the four that reported no `avx512f` in `/proc/cpuinfo` are the target runs.

## Results

| CPU | `avx512f` | File | Stock F1 | POPIA F1 | Gate | POPIA p50 |
|---|---|---|---|---|---|---|
| EPYC 7763 / 9V74 (4 shards) | no | `quint8_avx2` | 0.5464 | 0.7727 | **FAIL** (minimality) | 187.6–203.0 ms |
| EPYC 7763 / 9V74 (4 shards) | no | `qint8_avx512_vnni` | 0.2462 | 0.8004 | PASS | 148.6–163.0 ms |
| Xeon Platinum 8573C (control) | yes | `quint8_avx2` | 0.5464 | 0.7663 | **FAIL** (minimality) | 157.6 ms |
| Xeon Platinum 8573C (control) | yes | `qint8_avx512_vnni` | 0.4991 | 0.8115 | PASS | 56.6 ms |

All four AVX2-only shards produced identical F1 to four decimal places, so the accuracy numbers are
a property of the file and runtime, not of the individual runner.

- **On AVX2-only hardware:** qint8 is **+0.0277 POPIA F1 and ~20% faster** (−38.7 to −40.0 ms p50).
- **On VNNI hardware:** qint8 is **+0.0452 POPIA F1 and 2.8× faster**.
- The AVX2 file fails the per-clause rule on POPIA minimality / purpose limitation on every CPU
  tested. The qint8 file passes on every CPU tested.

## Two secondary findings

**The stock qint8 baseline collapses without VNNI** (0.4991 → 0.2462) while the POPIA fine-tune
barely moves (0.8115 → 0.8004). This is the signature of u8s8 weights saturating in `VPMADDUBSW`
on pre-VNNI x86 — the known reason onnxruntime recommends `reduce_range=True` for those CPUs. v1's
per-tensor fine-tune is robust to it; the stock cross-encoder's per-channel graph is not.
Consequence: on AVX2-only hardware a large part of the gate's delta-vs-stock margin comes from
stock degrading, not from POPIA improving. The gate still passes on the merits (POPIA 0.8004 in
absolute terms), but the *delta* should not be quoted as evidence of fine-tune quality there.

**Absolute latencies here are not publishable figures.** 149–203 ms on shared CI runners is far
above the documented ~15–70 ms envelope, measured locally on an i5-11320H (mean 50.7 / p50 44.3 /
max 98.8 ms). Shared vCPUs, a long premise, and no pinning make these numbers useful only as a
same-machine comparison between two files. Do not change public latency claims from them; if the
envelope needs restating, measure on real hardware.

## What this does not settle

Option (a) changes which file the library *selects*. It does not remove
`model_quint8_avx2.onnx` from the `nli-popia-v1` repo, and it must not: every already-installed
semantix ≤ 0.3.3 on Windows or Intel macOS requests that exact filename, and deleting it would
break those installs. So implementing (a) does **not** by itself turn the `popia-eval` job green —
the all-files gate scores every file shipped in the repo, and that file still fails.

Open for a product call:

- **(a1)** Library selects qint8 everywhere; the AVX2 file stays in the repo for old installs; the
  gate scopes to the files the current library can select, and the AVX2 file is recorded in docs as
  a known-failing legacy artifact. Turns CI green, keeps the disclosure.
- **(a2)** (a1) plus re-quantize and re-upload the AVX2 file with `reduce_range=True`, which would
  also fix already-installed versions. Needs a quantization + upload run on the model repo.
